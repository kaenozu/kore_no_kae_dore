# 商品特定計画

このドキュメントは、「これの替えどれ？」が将来的にどのように商品を特定していくかを整理したものです。

## 現仕様でできること

現在は電球（E26/E17）を対象に、以下の手順で候補を生成しています。

1. 写真を撮影し、画像分類で角度を判定
2. 手動で口金サイズ・明るさ・光色・器具対応を入力
3. 条件を組み合わせて候補名を生成
4. 検索用キーワードを提示

この段階では「完全な商品特定」は行っておらず、**条件一致候補**として提示しています。

## 完全な商品特定が難しい理由

- 写真だけでは型番やJANコードを正確に読み取れない
- 同一規格で複数のメーカー製品が存在する
- パッケージの印字は似たようなデザインが多い
- 現在の画像分類器は「角度」判定に特化しており、型番認識は未対応

## 型番/JANがある場合にできること

型番やJANコードが読み取れた場合、以下のメリットがあります。

- コード一致候補として信頼度を上げられる
- 検索キーワードが正確になる
- 価格比較・在庫確認が容易になる

ただし、読み取り精度は以下に依存します。

- カメラの解像度
- 印字の鮮明さ
- 照明条件
- コードの種類（JANはバーコード、型番は英数字）

## MatchLevelの意味

| レベル | 意味 | 現在の実装 |
|---------|---------|-----------|
| exactCode | 型番/JAN一致 | 未実装（将来対応） |
| compatibleSpec | 条件一致 | 現在の主力 |
| inferred | AI推定 | 写真分類時 |
| manualCandidate | 手動入力 | 手動フォールバック時 |

## 商品カテゴリ別の特定しやすさ

### 電球
- **条件一致向き**: 口金サイズ・明るさ・光色で十分な候補が絞り込める
- **完全特定は型番/パッケージが必要**: メーカー・シリーズまでは写真では難しい
- **目安**: compatibleSpec が主、型番OCRで exactCode へ昇格

### 電池
- **規格特定向き**: 単3/単4、アルカリ/充電、容量で十分
- **商品特定は不要寄り**: 規格が合えばどのメーカーでも可
- **目安**: compatibleSpec で十分な場合が多い

### プリンターインク
- **型番特定向き**: 対応機種・型番が固定されている
- **パッケージや型番OCRが有効**: バーコードや型番の読み取りで exactCode へ
- **目安**: exactCode を優先、OCR/バーコードスキャン必須

### 浄水器カートリッジ
- **型番/本体型番特定向き**: 同じシリーズでも旧型・新型があり得る
- **本体の型番確認が必要**: カートリッジ単体では型番が不明
- **目安**: exactCode を目指すが、本体型番入力が必要

### 空気清浄機フィルター
- **本体型番が重要**: 対応機種が専用設計のため
- **フィルター単体では型番が少ない**: 本体情報が必須
- **目安**: compatibleSpec で候補提示 → exactCode は本体型番確認後

### 掃除機紙パック
- **メーカー・対応機種が重要**: 互換性が機種に依存
- **型番または掃除機型番が必要**: パック単体では特定困難
- **目安**: compatibleSpec → 本体型番入力で exactCode

## 将来実装の優先順位

1. **型番OCR（priority: high）**
   - パッケージや商品本体の型番をカメラで読み取り
   - Tesseract / ML Kit Text Recognition を検討
   - 対応: 電球、インク、フィルター

2. **JAN/バーコード読み取り（priority: high）**
   - ML Kit Barcode Scanning でJANコード取得
   - 対応: インク、電池、交換フィルター

3. **商品検索連携（priority: medium）**
   - 楽天API / Amazon PA-API / YahooショッピングAPI
   - キーワード検索 → 候補リスト取得
   - MatchLevel.compatibleSpec / inferred で提示

4. **アフィリエイトリンク開示（priority: medium）**
   - 商品候補にリンクを含める場合の表示ルール
   - 「広告リンクを含みます」の明記
   - APIキー/アフィリエイトIDはアプリ直書き禁止（設定化）

5. **購入履歴入力（priority: low）**
   - ユーザーが過去の購入品を登録
   - 類似商品からの候補絞り込み
   - 信頼度の補強に使用

## 非目標

- 写真1枚で完全な商品特定は行わない
- 「同じ商品です」「これを買えばOK」のような断定表現は使わない
- 常にユーザー自身が最終確認できるだけの情報を提示する
